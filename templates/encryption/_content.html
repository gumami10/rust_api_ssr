How End-to-End Encryption Works

A visual guide to how Alice and Bob exchange encrypted messages through our chat, using hybrid cryptography. The server never sees plaintext.

The Full Flow

From key generation to encrypted message delivery.

RSA-OAEP 2048-bit

Each user generates an asymmetric key pair in their browser. The private key never leaves the device. The public key is uploaded to the server for others to fetch.

AES-GCM 256-bit

A symmetric room key encrypts all messages. Each encryption uses a fresh 96-bit IV, ensuring identical messages produce different ciphertext.

Server Sees Nothing

The server only stores encrypted room keys and ciphertext. It cannot read messages because it never has the room key in plaintext.

Step-by-Step Breakdown

1

Key Pair Generation

Alice and Bob each generate an RSA-OAEP 2048-bit key pair in their browser using the Web Crypto API. The private key is stored in localStorage and never sent to the server.

2

Public Key Upload

Each browser device uploads its public key to the server via POST /api/crypto/devices. The server stores per-device public keys in the user_devices table.

3

Fetch Recipient's Public Key

Alice fetches Bob's registered device public keys via GET /api/crypto/public-key/:userId so she can securely share the room key with each device.

4

Room Key Generation

Alice generates a symmetric AES-GCM 256-bit room key in her browser. This key will encrypt all messages in the room.

5

Room Key Distribution

Alice encrypts (wraps) the room key with each registered device public key using RSA-OAEP and uploads those wrapped copies to the server. The server stores them in chat_room_device_keys. Only the matching device can unwrap its copy.

6

Bob Decrypts the Room Key

Bob fetches the encrypted room key and decrypts it with his private key (RSA-OAEP). Now both Alice and Bob share the same AES room key.

7

Message Encryption

Alice encrypts her message with the AES room key. A fresh 96-bit IV is generated for each message. The output is IV + ciphertext, base64-encoded.

8-9

Ciphertext Relay

The ciphertext is sent to the server, which stores it (with is_encrypted = 1) and relays it to Bob via WebSocket. The server cannot read it.

10

Message Decryption

Bob extracts the IV from the first 12 bytes, then decrypts the ciphertext with the shared AES room key. The plaintext message is displayed.

Important Notes

  • E2E encryption is only active for 1-to-1 private rooms (exactly 2 participants).
  • All cryptographic operations happen in the browser using the Web Crypto API.
  • Private keys are stored in localStorage and never transmitted.
  • Clearing browser data will delete local keys, making old encrypted messages unrecoverable.
